# SBRT 그래픽의 의미와 관계 도식 v0.3

2026-11-14. 이번 자료는 시각 문법을 검토하기 위한 개념 도식이다. 새로운 연구 결과나 실제 대화 로그를 제시한 것이 아니다.

## 1. 이번 수정의 핵심

이전 색 채움 모듈은 동일한 사람과 모니터 안에서 문자만 바뀌어, 역할과 협업 방식의 차이가 잘 드러나지 않았다. 색 면적이 커지면서 카드형 UI처럼 보인다는 문제도 있다.

이번에는 밝은 바탕과 선 중심의 그래픽으로 돌아가고, AI를 칩으로, 협업 관계를 요청과 작업 대상, 출력, 피드백, 판단의 연결 구조로 표현했다. 사람과 AI의 식별 기호와 역할의 작용을 분리한다.

## 2. A–D 기호는 왜 그렇게 생겼는가

이 기호는 Buchanan이나 KIDP 원전의 공식 도상을 가져온 것이 아니다. 연구의 분야 정의를 설명하기 위해 제안한 시각적 은유다.

| 분야 | 형태의 설계 의도 | 읽기의 한계와 보완 방향 |
|---|---|---|
| A 기호와 의미 | 원은 기호나 메시지, 오른쪽 꺾쇠는 해석 범위, 연결선은 기호와 의미 맥락의 대응 | 꺾쇠가 의미를 나타낸다는 약속은 자의적이다. 설명 없이 읽기 어렵다. 실제 기호가 맥락 안에서 해석되는 관계를 확대도로 보여준 뒤 축약하는 방식이 더 적절하다 |
| B 사물과 물성 | 면과 모서리, 부피로 물리적 인공물을 표현 | 상자 형태는 패션과 텍스타일의 유연성을 충분히 대표하지 못한다. 입체와 유연한 표면의 결합을 다음 후보로 검토한다 |
| C 행동과 상호작용 | 열린 경계는 환경이나 인터페이스, 두 방향 표식은 작용과 응답 | 코딩의 꺾쇠처럼 보이며 실제 전달 방향도 불명확하다. 경계 양쪽의 접점과 명시적 왕복 선으로 정교화할 필요가 있다 |
| D 시스템과 서비스 | 노드와 연결선으로 요소 사이의 구조를 표현 | 네 노드는 실제 이해관계자 네 명을 뜻하지 않는다. 단순 연결망만으로 서비스의 작동 방식까지 설명되지는 않는다 |

공통 외곽 사각형은 범례에서 같은 크기로 비교하기 위한 표시 영역이다. 실제 시스템 경계라는 뜻은 없다. 분야의 범위는 기호 하나로 모두 전달하기 어려우므로 정의와 포함 분야, 필요하면 경계 사례를 함께 보여준다.

A 기호의 해석은 설계 의도를 설명하는 것이며, 형태가 이미 충분히 적절하다는 뜻은 아니다. A와 C는 특히 형태를 다시 다듬을 필요가 있다. 이번 설명 보드에서는 첨부 기호를 유지해 무엇이 의도였고 무엇이 불명확한지 구분했다.

## 3. 기존 4단계 기호의 의미

첨부 앱의 기존 기호를 유지하며 읽을 수 있는 활동의 은유를 정리했다. 선 하나하나가 원 논문에서 정의된 변수를 뜻하는 것은 아니다.

| 단계 | 기호의 해석 |
|---|---|
| Define | 교차선과 중심은 문제의 초점, 동심원은 주변 맥락과 문제 범위로 읽을 수 있다. 작은 점은 초점을 잡는 단서로 볼 수 있지만 실제 관측점은 아니다 |
| Ideate | 중심에서 바깥으로 뻗는 구조는 가능성과 대안의 확장을 나타낸다. 가지 아홉 개는 실제 아이디어 수가 아니다 |
| Evaluate | 외곽과 내부 구획은 비교와 선별, 중심은 판단 초점의 은유다. 현재 형태만으로 수렴의 작용이 충분히 읽히지는 않으므로 상세 도식에서 기준과 선택 경로를 보여주는 것이 좋다 |
| Deliver | 겹친 프레임은 결과물의 구체화, 체크는 완료의 은유다. 실제 작업 완료로 자동 판정하는 체크 표시는 아니다 |

기호의 마름모, 원, 사각형이 다른 위치에서 재사용되더라도 같은 의미라고 간주하지 않는다. 분야 표식, 단계 기호, 주체 기호를 각자의 자리와 제목으로 구분한다. 특히 Evaluate의 마름모는 분야 D의 의미가 아니다.

## 4. 주체: 사람과 칩

디자이너는 머리, 짧은 목과 어깨로 식별한다. 표정과 성별 표현은 넣지 않았다. 역할이 바뀌어도 사람 기호는 유지한다.

AI는 중심 코어, 외곽 패키지, 짧은 접점으로 구성한 칩으로 표현한다. 이는 정보 처리와 연결의 은유이며 실제 반도체 구조나 AI 시스템 아키텍처를 나타내지 않는다. 접점 수는 처리 능력, 연결된 도구 수 또는 입력 채널 수가 아니다.

역할 코드를 얼굴이나 칩 안에 반드시 넣을 필요는 없다. 이번 보드에서는 코드를 빼고 주변의 작용 구조와 완전한 역할 이름으로 읽게 했다. 앱의 축소 화면에서 필요한 경우에만 작은 코드 표식을 보조로 쓸 수 있다.

## 5. 협업 관계에 추가할 세 번째 요소: 작업 대상

두 주체만 선으로 잇는 것으로는 역할 차이를 설명하기 어렵다. 무엇을 주고받고 바꾸는지 보여주는 작업 대상을 추가한다.

- 브리프나 요청
- 자료 또는 맥락
- 시안과 아이디어
- 평가 기준이나 피드백
- 수정된 결과와 최종 반영본

범례의 문서 모양은 모든 작업 대상을 대표하는 임시 기호다. 실제 적용 때에는 브리프, 시안, 피드백 등을 명시적으로 이름 붙이며, 이미지가 있으면 축소 이미지를 해당 위치에 넣을 수 있다.

## 6. AI 역할을 작용 구조로 구별하기

| 역할 | 이번 개념도의 중심 작용 | 유의점 |
|---|---|---|
| Generator | 생성 요청이 여러 대안으로 분기 | 한 번의 생성으로 끝난다는 뜻이 아니다. 중심 작용을 보여주기 위해 후속 피드백은 생략했다 |
| Assistant | 사람이 정한 작업 범위를 AI가 수행하고 결과가 돌아옴 | 반복 수정과 대화가 있을 수 있다. 핵심은 맡기는 일과 범위를 사람이 설정한다는 안내다 |
| Advisor | 기존 안이나 상황을 검토해 피드백하고 사람이 반영 여부를 판단 | 기존 안은 시각 시안뿐 아니라 계획이나 문제 상황일 수도 있다. 피드백은 명령이나 자동 승인으로 표현하지 않는다 |
| Co-creator | 공유된 작업 대상을 매개로 제안과 변형이 반복 | 왕복선이 있다고 모두 공동창작은 아니다. 함께 안을 발전시키는 기여를 설명한다 |

이 네 구조는 역할을 이해하도록 만든 예시다. 정확한 메시지 순서나 권한 배분을 고정하는 프로토콜이 아니다. 네 역할 모두 실제로는 왕복 대화를 포함할 수 있으며 역할 간 활동도 겹칠 수 있다.

## 7. 디자이너 역할도 작용으로 구별하기

| 역할 | 시각적으로 드러낼 작용 |
|---|---|
| Evaluator | 여러 안을 기준에 비추어 선택 또는 제외 |
| Interpreter | 자료나 산출물을 맥락에 비추어 해석하고 의미를 재구성 |
| Orchestrator | 도구, 작업, 자원과 이해관계자의 연결 및 순서를 조율 |
| Value-creator | 지향할 목적과 가치를 정의하고 판단 기준과 결과에 반영 |

이번 보드의 위쪽 네 AI 역할과 아래쪽 네 디자이너 역할은 일대일 짝이 아니다. Generator가 반드시 Evaluator와만 협업한다는 뜻도 아니다.

전체 협업 모듈에서는 AI 작용과 디자이너 작용을 하나의 작업 대상을 중심으로 결합한다. 예를 들어 Generator + Interpreter는 AI가 대안을 생성하고 디자이너가 그 대안의 의미를 맥락 속에서 해석하는 관계로 그릴 수 있다. 이는 예시이며 어떤 분야의 검증된 최적 조합이라는 뜻은 아니다.

## 8. 선의 문법: 세 종류의 지도를 섞지 않기

| 표현 수준 | 선의 의미 | 필요한 근거 |
|---|---|---|
| 역할 설명용 개념도 | 요청, 결과, 피드백의 전달과 작용 | 역할 정의와 연구자의 설명. CONCEPT로 표시 |
| 참여자별 단계 경로 | 같은 참여자가 선택한 역할이 단계별로 어떻게 바뀌는지 | chips.json 등의 단계별 응답. 실제 대화 순서라고 주장하지 않음 |
| 실제 작업 과정 기록 | 실제 요청, 생성 결과, 수정과 판단의 순서 | 해당 작업의 기록 또는 로그 |

화살표는 전달이나 순서를 뜻한다. 화살표가 없는 선은 단순 관계나 참조 연결로 제한하고 필요하면 라벨을 붙인다. 파선은 주석 연결에 사용하며, 동시에 불확실성이나 가상 데이터라는 뜻으로 중복 사용하지 않는다.

실제와 이상은 명시적인 ACTUAL / IDEAL 표제와 동일한 구성의 별도 화면으로 비교한다. 이상 관계를 실제 일어난 과정처럼 연결하지 않는다.

두꺼운 띠는 실제로 집계한 공유 경로 수가 있을 때만 사용한다. 이번 개념도에서는 선 굵기와 요소 크기를 수치에 대응시키지 않았다. 인터뷰의 역할 쌍만으로 실제 메시지 교환 과정을 복원하지 않는다.

## 9. 색과 밀도의 방향 수정

큰 색 면을 기본으로 삼는 카드형 구성에서 밝은 바탕, 가는 선, 접점, 작은 표식, 주석 중심으로 돌아간다. 분야색은 분야 표식, 선택한 경계, 관련 경로 등 제한된 위치에 사용한다. 역할 자체에는 새로운 색 체계를 만들지 않는다.

색 채움은 선택 상태나 특별한 확대 패널에서만 사용할 후보로 남긴다. 장식용 선과 숫자를 늘리지 않고, 전달의 방향, 작업 대상, 판단 지점을 추가하여 정보의 밀도를 만든다.
