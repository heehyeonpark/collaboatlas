# SBRT 전시 앱과 아틀라스: 정보 구조 및 그래픽 설계안 v0.2

작성일: 2026-11-14
상태: 구상 정리 및 편집 가능한 그래픽 시안. 앱 구현 및 실증 분석 완료본이 아니다.

## 1. 프로젝트의 목적

이 앱은 SBRT 연구를 설명하고, 디자이너가 자신의 디자인 과제에 맞게 AI와의 협업 역할을 조정하도록 안내하며, 실제 협업 과정을 기록하여 설명 자료로 활용하도록 돕는다.

핵심 기능은 세 가지다.

1. Understand: 연구 배경과 SBRT 모델을 이해한다.
2. Collaborate: 분야와 단계에 맞는 협업 구조, 관계 메타포, 요청 방식, 디자이너의 판단 항목을 참고한다.
3. Record: 실제 요청, 생성 결과, 수정과 판단, 최종 반영 내용을 글과 이미지로 기록하고 내보낸다.

연구 지도는 안내의 근거이며, 기록은 안내를 따랐다는 점검표가 아니라 실제 작업 과정의 설명이다. 제안과 다른 협업도 기록할 수 있어야 한다.

## 2. 확인된 자료와 근거 상태

이전 턴에서 확인한 첨부 ZIP의 app.js, atlas.js, chips.json, 설계_프롬프트.md와 기존 69쪽 논문 PDF를 토대로 정리했다. 이번 사용자의 설명을 기능과 시각 방향의 최신 요구사항으로 반영했다.

- 설문: 설계 문서에 전체 n=43, 분야별 최다 역할, 단계별 전체 AI 자율성 평균이 정리되어 있다. 분야별 표본 수, 전체 분포, 검정표는 아직 확인하지 못했다.
- 인터뷰: 소스에 12명, 분야별 3명의 실제 48좌표와 이상 48좌표가 있다. 원 인터뷰 발언, 정확한 질문 문구와 코딩 기준은 확인하지 못했다.
- 기존 논문 PDF: 실증 검증을 향후 계획으로 설명하고 있어 최신 결과의 근거로 삼지 않는다. 현재 MD와 역할 위계, Zone 이름에 차이가 있다.
- 여러 방법론의 4단계 대응과 Buchanan–KIDP 통합은 사용자의 연구 구성이다. 이번 문서에서 원전 대조나 타당성 검증을 새로 완료한 것은 아니다.

## 3. 첫 번째 파트: Understand the model / 연구 이해

### 3.1 왜 네 단계인가

관람자가 알아야 할 핵심은 서로 다른 방법론의 활동을 어떤 기준으로 네 단계에 대응시켰는가이다.

- Define: 문제와 맥락을 해석하고 방향을 설정한다.
- Ideate: 가능성과 대안을 생성하고 탐색한다.
- Evaluate: 기준에 따라 대안을 평가하고 수렴시킨다.
- Deliver: 결과를 구체화하고 최종 산출물을 정리한다.

그래픽은 ‘방법론별 원래 단계 → 활동의 대응 근거 → SBRT 4단계’의 정렬표로 제작한다. 각 방법론의 순환, 반복, 경계 차이는 유지한다. 모든 디자인 방법론이 본질적으로 동일한 네 단계라는 주장으로 단순화하지 않는다.

전시 문구 초안:
> 본 연구는 여러 디자인 방법론의 활동을 문제정의, 아이데이션, 평가와 수렴, 최종산출의 네 단계로 재구성하여 AI와 디자이너의 역할 변화를 비교한다.

필요 자료: 논문에서 실제 비교한 방법론 목록, 원래 단계명, 대응 기준과 인용 위치.

### 3.2 왜 네 Axis인가

Buchanan의 디자인 영역 관점과 KIDP 분류를 어떻게 통합하여 연구의 네 Axis를 구성했는지 보여준다.

| Axis | 전시용 중심 개념 | 현재 MD의 포함 분야 | 그래픽 접근 |
|---|---|---|---|
| A | 기호와 의미 | 시각, 정보, 브랜딩, 디지털미디어 | 표식과 해석 범위의 대응 |
| B | 사물과 물성 | 제품, 패션, 텍스타일, 산업공예 | 면과 부피를 가진 형태 |
| C | 행동과 상호작용 | UI/UX, 인터랙션, 공간환경 | 경계를 넘나드는 상호작용 |
| D | 시스템과 서비스 | 서비스, 경험, 융합, 전략 | 요소와 요소 사이의 연결 구조 |

그래픽은 원 이론, 원 분류의 항목과 최종 Axis를 연결하는 출처 있는 대응표로 만든다. 원전의 명칭과 본 연구의 재명명을 구별한다. 현재 영어 제목은 전시용 제안 명칭이며 논문의 공식 명칭은 최신본으로 확인한다.

각 Axis에 정의, 다루는 문제, 포함 분야, 대표 과제, 인접 Axis와의 구분 기준을 둔다. 복수 Axis 과제의 분류 방식은 연구자의 기준 확인 후 정한다. A에서 D로 갈수록 더 우수하다는 인상을 주지 않는다.

### 3.3 왜 AI와 협업하는가

AI가 제공할 수 있는 생성, 정리, 피드백, 공동 발전의 기여와 디자이너의 평가, 해석, 조율, 가치 판단을 함께 설명한다. 협업의 필요는 ‘AI를 많이 쓸수록 좋다’가 아니라 과업 목적에 맞는 기여와 판단의 조직으로 제시한다. AI를 쓰지 않거나 중단한 결정도 기록할 수 있다.

그래픽: 사람과 모니터의 쌍, 그 사이의 작업 대상, 역할이 교체되는 네 단계. 비율이나 크기로 양자의 가치를 배분하지 않는다.

### 3.4 SBRT는 무엇인가

앱용 설명 초안:
> SBRT는 디자인 분야와 단계의 맥락에 따라 AI와 디자이너의 역할을 조정하는 협업 프로세스 모델이다. 지금 무엇을 AI에게 맡기고 무엇을 스스로 판단할지 정리하고, 다음 단계에서 수행할 작업을 구체화하도록 돕는다.

문제의식은 특정 단계에서 생성이나 수정만 반복하거나, 다음 단계에서 무엇을 해야 할지 몰라 작업이 멈추는 상황이다. 발생 빈도나 인과 관계는 근거가 있는 범위에서만 제시한다.

‘단계 정체를 예방한다’는 현재 모델이 지향하는 효과이자 검증할 가설로 표시한다. 효과 검증 자료가 확보되면 연구 설계와 결과를 별도로 연결한다.

그래픽: 반복 중인 단계와 다음 단계에서 필요한 판단을 보여주는 개념도. 실제 발생 기록이 없으면 CONCEPT 또는 HYPOTHESIS로 표기한다. 역할 전환을 했기 때문에 병목이 실제로 해소되었다는 효과 도표는 만들지 않는다.

## 4. 두 번째 파트: Explore collaboration / 분야별 협업 제안

### 4.1 화면의 순서

분야 선택 → 분야의 특성 → 관찰된 경향 → 단계별 협업 모듈 → 메타포와 요청 방식 → 실제 기록 시작.

각 단계 모듈은 동일한 구조를 사용한다.

| 항목 | 내용 |
|---|---|
| Context | 해당 분야와 단계에서 다루는 문제 |
| Suggested roles | 제안하는 AI와 디자이너의 역할 및 대안 |
| Metaphor | AI를 어떤 동료처럼 대하면 좋은지 |
| Ask | 작업 목적, 조건, 범위와 중단 지점을 담은 요청 예시 |
| Decide | 디자이너가 해석하고 결정할 사항 |
| Move on | 다음 단계로 넘어가기 위해 확인할 사항 |
| Evidence | 어떤 설문 또는 인터뷰 관찰과 연결되는지 |
| Record | 실제 협업을 짧게 기록하는 입력 진입점 |

메타포와 요청문은 자료의 직접 인용인지 연구자가 구성한 안내인지 구분한다. 단계별 대표 메타포를 두되 모든 분야와 상황에 고정하지 않는다.

### 4.2 안내 예시: 아이데이션

아래는 안내 구조를 설명하기 위한 작성 예시이며 검증된 최적 조합이 아니다.

- AI 역할: Generator
- 디자이너 역할: Interpreter
- 메타포: 서로 다른 시안을 빠르게 제안하는 손 빠른 팀원
- 요청 예시: ‘이 방향을 바탕으로 서로 다른 콘셉트 세 가지를 제안하고 차이를 설명해 줘.’
- 내가 판단할 것: 각 안의 의미와 적합성, 더 발전시킬 방향
- 다음 단계 확인: 비교할 대안과 평가 기준이 준비되었는가
- 실제 기록: 요청과 시안, 선택 또는 제외한 이유

### 4.3 연구 관찰에서 제안으로 넘어가는 과정

관찰 → 연구자의 해석 → 협업 제안을 명시적으로 연결한다. 설문 최빈값을 자동으로 최적 역할로 변환하지 않는다. AI와 디자이너 각각의 최다 선택이 반드시 공동 조합 최빈값을 뜻하지 않는다.

서론의 잠정 문구:
> 전문가 43명의 설문과 12명의 인터뷰를 바탕으로 분야와 단계에 따른 역할 선택의 맥락을 탐색하고, 이를 참고할 수 있는 협업 구조로 제안한다.

‘분야별 유의미한 차이’ 표현은 최신 분석표 확인 전에는 확정하지 않는다. 이전 MD는 다중비교 보정 후 분야 간 차이가 유의하지 않았다고 명시했다. 사용자가 강조한 문제정의와 최종산출의 차이는 통계적 차이, 기술적 분포 차이, 질적 맥락 차이 중 어느 근거인지 확인한다. 비유의 결과는 차이가 전혀 없다는 증명도 아니다.

### 4.4 개인 응답과 큰 흐름의 그래픽

목표는 전체 응답을 숨기지 않으면서 공통 경향을 쉽게 읽게 하는 것이다.

- 배경 가는 선: 익명 참여자의 연결된 단계별 응답.
- 전경 반투명 띠: 같은 출발 역할과 도착 역할을 공유하는 응답 수. 실제 인원수에 비례해 폭을 부여하고 n과 범례를 표기한다.
- 노드: AI 역할만인지, 디자이너 역할만인지, 두 역할의 쌍인지 명확히 구분한다. 협업 관계를 표현하는 주요 지도에는 역할 쌍을 우선 검토한다.
- Actual와 Ideal: 동일 규격의 별도 패널. 두 상태를 하나의 경로처럼 섞지 않는다.
- 분야색: 패널 또는 경로에 일관되게 적용한다. 여러 분야를 비교할 때 표본 크기와 분모를 명시한다.
- 경로가 공유되지 않으면 굵은 공통 경로를 만들지 않는다. 노드 선택이 반복되는 것과 단계 간 전환이 반복되는 것은 다른 정보다.
- 역할 좌표의 평균으로 대표 곡선을 만들지 않는다. 역할 범주는 연속 수치가 아니며 아무도 선택하지 않은 조합이 생길 수 있다.
- 인터뷰 분야별 n=3은 사례의 공통점과 차이를 보여주는 자료로 사용한다. 분야 전체의 모집단 추세로 확대하지 않는다.
- 설문에서 참여자별 연결 자료가 없다면 역할 분포를 각각 표시하며, 가상의 흐름을 연결하지 않는다.

새 시안에는 근거 없는 굵은 띠를 넣지 않았다. 전체 지도에 실제 띠를 그릴 때에는 원 자료의 연결 가능성과 빈도를 계산한 뒤 반영한다.

## 5. 세 번째 파트: Record your process / 협업 로그

### 5.1 기본 경험

디자이너가 AI 도구 옆에 열어 두고 현재 단계를 선택하여 짧은 글과 주요 이미지를 남긴다. 단계를 오가거나 이전 단계로 돌아갈 수 있다. 반복 기록은 덮어쓰지 않고 추가할 수 있도록 설계한다.

빠른 기록의 필수 입력은 최소화한다.

1. AI와 무엇을 했는가
2. 내가 무엇을 선택하거나 수정했는가
3. 글이나 이미지 첨부: 선택 입력

도구, 날짜, 실제 역할, 요청 전문, 결과 설명 등은 펼쳐 입력할 수 있다. 자동으로 알 수 없는 정보는 추정해서 채우지 않는다.

### 5.2 권장 기록 구조

| 수준 | 항목 |
|---|---|
| 프로젝트 | 제목, 목적, 분야, 설명, 공개용 표기 |
| 작업 항목 | 단계, 기록 시각, 실제 사용 역할, 사용 도구, 요청, 생성 결과, 판단과 수정, 최종 반영 여부 |
| 이미지 | 생성 시안, 디자이너 수정안, 최종 반영본 구분, 캡션과 출처 메모 |
| 선택 첨부 | 대화 링크, 추가 문서, 상세 요청문 |

제안 역할과 실제 역할은 별도 필드로 둔다. 실제 역할의 단일·복수 선택 허용 여부는 연구와 기록 도구의 목적을 구분해 결정한다. 연구 응답에 없던 복수 역할을 연구 데이터처럼 집계하지 않는다.

### 5.3 저장과 출력

목표 출력은 다음과 같다.

- AI 활용 요약서: 단계별 사용 목적, AI 기여, 디자이너 판단, 최종 반영 범위.
- 협업 과정 상세 기록: 요청문, 주요 이미지, 수정 내용과 판단 이유.
- 다시 편집할 수 있는 프로젝트 자료: 글과 이미지가 함께 복원되는 형태.

권장 구현 방향은 PDF 요약 및 상세 보고서와 편집 재개용 데이터·첨부 이미지 묶음이다. 현재 앱의 텍스트 중심 저장에서 이미지 첨부, 용량 관리, 백업과 복원 설계가 추가로 필요하다. 최종 저장은 브라우저 내부 저장과 별도 파일 내보내기를 구분해야 한다. 이 기능들은 아직 구현되지 않았다.

자동 대화 수집을 전제하지 않고 직접 입력, 붙여넣기, 첨부를 기본으로 한다. 내보내기 전에 포함할 항목을 선택하고 문서를 검토할 수 있도록 한다. 기관의 승인이나 공인 증명을 보장하지 않으며 제출처 양식에 맞게 구성할 수 있는 기록이다.

## 7. 전시용 아틀라스 구성

포스터는 웹 화면을 그대로 확대하지 않고, 상시 보이는 범례와 주석을 갖춘 독립적인 읽기 구조로 만든다.

- 상단: 연구의 질문, 방법론의 4단계 재구성, 4 Axis 도출, SBRT 정의.
- 중앙: 네 단계의 공통 열 구조, 분야별 협업 지도, 역할 전환의 공통점과 차이, 실제와 이상 비교.
- 측면 또는 확대 패널: 주체와 역할 범례, 대표 협업 모듈, 관계 메타포와 요청문, 근거 및 한계.
- 하단: 개인 기록의 구조, 공개 가능한 사례, 활용 내역 출력 예시, 연구에서 관찰한 내용과 제안한 내용의 구분.

앱에서는 접고 펼칠 수 있는 설명을 포스터에서는 인접 주석으로 둔다. 실제 출력 크기, 가로·세로, 관람 거리와 설치 면적은 아직 미정이므로 글자 크기와 정보량을 최종 확정하지 않았다. 이번 세로형 구성은 정보 위계 검토용이지 최종 판형 결정이 아니다.

## 8. 이번 산출물의 읽는 법

- SBRT_v02_graphic_system.svg: 사람·모니터 기호, 네 분야의 색 채움, 안내·근거·기록 연결. 네 분야에 같은 As+I를 넣은 것은 그래픽 비교용이며 분야별 제안 결과가 아니다.
- SBRT_v02_atlas_structure.svg: 세 파트를 한 장에 배열한 구조도. ROLE PAIR는 채워야 할 위치를 뜻한다. 미확인 연구 결과를 대신하는 가짜 데이터가 아니다.
- PNG는 미리보기이며 SVG의 text, path, rect, circle을 편집할 수 있다. 사용 글꼴은 Noto Sans CJK KR. 편집 프로그램의 글꼴 설치와 SVG 가져오기 방식에 따라 텍스트 처리 차이가 있을 수 있다.
- 원 앱 코드는 수정하지 않았다.

## 9. 다음 작업의 우선순위

1. 시각 검토: 사람과 모니터의 추상화 정도, 색을 채운 협업 프레임의 인상 확정.
2. 연구 정합성: 최신 논문의 4단계 및 Axis 도출, 역할 정의와 Zone, 실증 결과 부분 대조.
3. 데이터 지도: 설문 원자료 또는 분야·단계별 분포 및 연결 자료를 확보해 집계 방식 확정. 문제정의와 최종산출 차이의 근거 확인.
4. 내용 설계: 분야 × 단계 16개 모듈에 근거, 해석, 제안, 메타포, 요청문, 판단과 다음 단계 확인 항목 작성.
5. 사례 적용: 실제 공개 가능한 작업 하나에 안내와 로그 구조를 적용하고 읽기 점검.
6. 전체 아틀라스: 실제 판형에 맞춰 편집 가능한 SVG 도판으로 구성.
7. 앱 구현: 정보 구조가 정리된 뒤 단계별 안내, 이미지 기록, 저장·복원·내보내기 구현.

전체 목적과 기능 구조는 추가 설명 없이 진행할 수 있다. 남아 있는 것은 의도의 불명확함보다 최신 연구 근거와 전시 제작 조건의 확인이다.
